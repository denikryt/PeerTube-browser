# Crawler Compatibility Decisions

## Purpose

This document records crawler compatibility decisions that preserve working crawler behavior while the crawler database layer is refactored. Each decision states the reason, implementation action, tests, and removal condition so compatibility behavior is explicit rather than hidden in code movement.

## Stage 7: crawler database split

### `db.ts` remains a facade

Decision:

```text
engine/crawler/src/db.ts remains the public compatibility import path for crawler stores and exported types.
```

Reason:

```text
Existing workers and local scripts import CrawlerStore, ChannelStore, VideoStore, and row types from ./db.js. Removing that path would turn a database-module split into a caller migration.
```

Implementation action:

```text
Move store implementations into engine/crawler/src/db/*.ts and reduce engine/crawler/src/db.ts to re-exports only.
```

Tests:

```text
engine/crawler/test/db/*.test.ts import stores through ../../src/db.js and exercise persisted SQLite state.
```

Removal condition, if any:

```text
A later crawler caller-migration stage may remove the facade only after repository-wide and documented local-script import compatibility is replaced.
```

### Crawler command names remain unchanged

Decision:

```text
Existing npm crawler command names and their generated dist entrypoint paths remain unchanged.
```

Reason:

```text
Data-build docs, operators, and updater jobs rely on the current command surface. Stage 7 is a database-layer split, not a CLI migration.
```

Implementation action:

```text
Do not rename existing package scripts, CLI files, worker function signatures, or generated dist paths. Add only the new test:db script.
```

Tests:

```text
make build-crawler in environments with Node dependencies verifies the unchanged command entrypoints compile.
```

Removal condition, if any:

```text
Only a dedicated crawler CLI/deployment plan may rename commands.
```

### `schema.sql` remains unchanged

Decision:

```text
engine/crawler/schema.sql remains the source of truth for the crawler raw crawl DB shape and is not changed in Stage 7.
```

Reason:

```text
Engine jobs and Engine read paths consume the crawler output schema. Stage 6 already documented schema ownership; Stage 7 only reorganizes the TypeScript DB implementation.
```

Implementation action:

```text
Move the existing runtime compatibility migration helpers into db/schema.ts and keep applyBaseSchema behavior equivalent.
```

Tests:

```text
Stage 6 schema compatibility tests remain green, and Stage 7 crawler DB tests create rows through stores and inspect SQLite state directly.
```

Removal condition, if any:

```text
Schema changes require a future schema/data-build migration plan.
```

### Progress table status and error semantics are preserved

Decision:

```text
Instance, channel, and video progress tables keep their current status, timestamp, error, and counter behavior.
```

Reason:

```text
Resume/retry behavior depends on these fields. Changing them during a module split would risk silent crawl skips, duplicate work, or broken recovery.
```

Implementation action:

```text
Move progress SQL mechanically into instances.ts, channels.ts, and videos.ts. Keep status values, ordering, timestamp writes, and error increments unchanged.
```

Tests:

```text
engine/crawler/test/db/instances.test.ts, channels.test.ts, and videos.test.ts assert progress rows directly after store actions.
```

Removal condition, if any:

```text
Any progress semantic change requires a later crawler behavior plan with before/after migration notes.
```

### `dist/` remains generated, ignored, and not committed

Decision:

```text
engine/crawler/dist/ remains generated by npm run build and stays ignored by Git.
```

Reason:

```text
Runtime jobs may execute generated JS files, but generated artifacts should not be committed. Stage 7 adds dist-test/ for test builds with the same ignored-artifact policy.
```

Implementation action:

```text
Do not commit dist/ or dist-test/. Document test/build commands and keep generated paths stable.
```

Tests:

```text
make build-crawler and make test-crawler-db verify generated output in environments with Node dependencies.
```

Removal condition, if any:

```text
Only a later build/deployment plan may change generated output paths.
```
