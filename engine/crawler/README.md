# Crawler

Collects and updates data from PeerTube instances and stores it in SQLite. This component owns PeerTube data collection and crawler database writes. It does not own ranking, Engine API routing, Client profile state, or UI behavior.

## Layout

```text
src/*-cli.ts          CLI entrypoints for crawler commands
src/*-worker.ts       PeerTube traversal, pagination, concurrency, and retry orchestration
src/crawler.ts        instance crawl traversal
src/db.ts             compatibility facade for crawler database stores
src/db/               connection, schema compatibility, types, and store modules
schema.sql            raw crawler DB schema source of truth
```

## Entry points

```bash
npm run build
npm run crawl:instances
npm run crawl:instances:health
npm run crawl:channels
npm run crawl:channels:health
npm run crawl:channels:videos-count
npm run crawl:videos
npm run crawl:videos:tags
npm run crawl:videos:comments
npm run crawl:videos:thumbnails
```

## Tests

Crawler DB tests require local Node dependencies and compile to ignored `dist-test/` output:

```bash
npm install
npm run test:db
```

These tests use temporary SQLite files and do not run real PeerTube network crawls.

## Notes

`dist/` is generated by `npm run build`, remains ignored by Git, and is used by jobs or operators that execute compiled crawler CLIs.

Normal `npm run crawl:videos` now enriches thumbnail and preview media from
`/api/v1/videos/:uuid` during ingestion. The list payload is still kept as a
fallback when a host's detail endpoint fails, so the crawl remains resilient
while preferring fresher stored media URLs.
